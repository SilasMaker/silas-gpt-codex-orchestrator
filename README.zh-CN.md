# Silas GPT Codex Orchestrator

[English](README.md) | 简体中文

**让 ChatGPT 帮你想方案、检查成果，让 Codex 动手制作，你来决定是否好用。**

从一个想法，到一个可以打开体验的小项目：你描述目标，Codex 组织 ChatGPT 一起讨论、执行和复核，把实际成果与检查结果交到你手里。连接服务按需启动。

## 它是什么

这是一套让 Codex 组织 ChatGPT 参与项目工作的 Skill。你可以把它理解为一份可执行的协作方法：谁先看项目、怎样讨论方案、如何交付修改、用什么证据复核，都有明确的流程。

| 参与者 | 在这套流程中的分工 |
|---|---|
| 你 | 提出目标，选择项目和共享范围，试用成果并反馈 |
| ChatGPT | 读取获准的项目资料，参与规划，复核改动和检查记录 |
| Codex | 核实方案，实际修改文件、运行检查、操作预览，并转交消息 |

Codex 本身也能规划和复核。这种分工让双方围绕同一份项目与证据工作，不要求使用两个不同的模型，也不固定某个模型版本。

### 可以用来做什么

- **做一个小网页：** 个人介绍页、任务清单、作品展示页。
- **增加一个小功能：** 给任务清单加入重置、撤销或筛选操作。
- **排查一个具体问题：** 比如刷新后进度丢失、手机按钮被遮挡。
- **迭代实际体验：** 先做可运行的小版本，再根据你的反馈修改。

不必先学会写代码。第一次可以只说：“我想做一个能打勾的任务进度页，刷新后进度还在。”越具体的目标，越容易得到可验证的结果。

## 为什么让两个 AI 协作

**少做两个 AI 之间的传话人，多得到一轮针对实际成果的检查。**

| 方式 | 适合的任务 | 使用时的区别 |
|---|---|---|
| GPT 普通聊天 | 讨论想法、整理需求、比较方案 | 没有连接执行工具时，需要你把方案落实，再带回结果 |
| Codex 单独执行 | 明确的修改、日常开发、运行检查 | 可以直接交办，步骤更少；也能自行规划和复核 |
| 本 Skill 协作 | 值得反复讨论、制作和复核的项目 | Codex 转交消息，ChatGPT 按需读项目，双方核对本轮成果 |

连接可用时，Skill 帮你减少复制方案、代码和报错的操作；让 ChatGPT 从另一个对话视角检查成果；记录任务与代码版本，减少看着旧文件评价新结果的混乱。

**同一个界面方便查看，实际连接负责互通。** 你可以在 Codex 中同时看到 ChatGPT 讨论和项目预览。单纯把两个窗口摆在一起不会自动协作，也不会提升模型本身的能力。

首次配置和额外讨论会增加等待与模型使用量。改一句文案、修一个明确的小问题，直接用 Codex 通常更省事。双方也可能犯同样的错误，所以复核仍需要真实测试和你的试用反馈。

## 一段话安装


不用自己先学会 git、Node 或终端操作。把下面这段话复制给 Codex，让它检查环境并带你安装；账号登录和必要授权仍需要你参与。

安装来源为本仓库；如果已经下载，也可以提供实际的本地 Skill 文件夹路径。

```text
请帮我安装并配置 Silas GPT Codex Orchestrator。安装来源：https://github.com/SilasMaker/silas-gpt-codex-orchestrator。我是新手，请尽量替我完成可以自动处理的步骤，用简单的话告诉我进度。

1. 先读取这个 Skill 的说明，检查本机环境、已有安装和连接状态。按文档准备必要依赖，复用可用环境，保留已有个人修改；不自动购买服务或升级套餐。
2. 安装完整的 silas-gpt-codex-orchestrator 文件夹到当前 Codex 使用的 skills 目录，包括说明、引导、脚本和运行源码，不能只复制 SKILL.md。按文档准备运行组件，检查 Codex 能否识别；如果需要新开对话或重启，请告诉我下一步。
3. 用简单的话介绍它能做什么。为首次连接使用一个独立、无敏感内容的测试项目，只允许 ChatGPT 读取这个项目。
4. 按随附连接指南，根据当前账号与本机条件配置支持的连接方式。可用时使用 Codex 内置浏览器；确实需要我登录、验证码或授权时，一次只告诉我一个必要动作。密码和密钥留在安全的本机配置或对应网页，不让我粘贴进聊天。
5. 让 ChatGPT 真实读取测试项目，再修改测试文件、重新读取并核对新内容，确认不是只安装了文件或只显示“已连接”。若连接不可用，说明具体卡点并保留进度，不把模拟或人工转发说成自动连通。
6. 完成后给我一份简短结果：Skill 是否已安装并被识别、ChatGPT 是否真实连通、测试是否通过、还有什么需要我处理，以及开始第一个小项目可以直接复制的一句话。验证结束后按需关闭本轮启动的连接服务。
```


### 已下载文件，想自己安装

1. 找到完整的 `silas-gpt-codex-orchestrator/` 文件夹，内部应包含 `SKILL.md`、`agents/`、`references/`、`scripts/` 和 `runtime/`。
2. 将整个文件夹放入当前 Codex 使用的 skills 目录。常见位置为 `~/.codex/skills/`；使用自定义配置时，以实际目录为准。已有同名版本时先核对本地修改。
3. 让 Codex 读取该 Skill，按 [连接指南](silas-gpt-codex-orchestrator/references/connection.zh-CN.md) 准备运行组件并检查连接。如果当前对话未识别新安装的 Skill，按应用提示重新加载或新开对话。

仅复制 `SKILL.md` 不够；运行源码也需要准备依赖和构建。安装文件本身不会自动启动欢迎对话、建立连接或创建项目。

## 安装后怎么开始

### 第一次试用

在能够读取该 Skill 的 Codex 对话中发送：

```text
使用 $silas-gpt-codex-orchestrator。我是第一次使用，请先用简单的话介绍用途，检查我还缺哪些准备。连接就绪后，带我用一个独立演示项目做可交互的任务进度页：能勾选任务、显示进度，刷新后保留结果。先做一个能体验的小版本，完成后给我预览和实际检查结果。
```

Codex 会先检查准备状态，再处理必要的连接步骤。需要你登录、验证码或新的共享授权时，告诉你当前要完成的动作；已有明确目标和授权时直接继续。

### 已有项目

在该项目的 Codex 对话中说：

```text
使用 $silas-gpt-codex-orchestrator，在当前项目给任务清单增加“重新开始”和一次“撤销”功能。先核实连接，只做这一个小改动，完成后给我预览与真实检查结果。
```

### 继续修改或恢复中断

```text
手机里“重新开始”按钮不容易发现。请让 ChatGPT 和 Codex 一起检查，只调整这个操作区，再给我手机预览。
```

```text
继续刚才的协作，先检查已完成的内容和连接状态，不要从头重做。
```

你描述想要的结果和观察到的问题即可。更完整的例子见 [新手入门指南](silas-gpt-codex-orchestrator/references/getting-started.zh-CN.md)。

## 怎样判断安装和协作成功

这几个状态需要分别确认：

| 状态 | 应该看到的证据 |
|---|---|
| Skill 已就绪 | 安装文件完整，Codex 能读取说明并按要求引导 |
| 项目已选定 | 清楚显示本次项目及允许分享的范围 |
| ChatGPT 真实连通 | 实际读到测试文件；文件变化后再次读到新内容 |
| 本轮制作完成 | 本地文件确实修改，提供实际执行的检查结果 |
| 本轮复核完成 | ChatGPT 检查本轮代码和对应记录，给出结论或修改意见 |
| 可以体验 | 有可打开的成果，明确还有哪些地方未验证 |

只有对应检查通过，才应显示该项完成。设置页显示“已连接”不能代替真实读取，模型说“做好了”也不能代替运行和体验。

第一次拿到任务页，试着勾选任务、刷新页面、缩窄窗口。看进度是否变化、是否保留，以及操作是否仍然方便。工程检查通过后，你的体验反馈决定下一步。

## 工作过程

```mermaid
flowchart LR
    U[你提出目标] --> G[ChatGPT 读取项目并规划]
    G --> C[Codex 核实方案并制作]
    C --> T[运行检查与实际体验检查]
    T --> R[ChatGPT 读取本轮代码与证据]
    R -->|需要修改| C
    R -->|工程检查通过| P[交给你预览与验收]
```

Codex 在授权范围内把任务和报告转交给 ChatGPT；ChatGPT 通过只读 MCP 按需读取项目文件与执行记录。你可以先把 MCP 理解为“读取已选项目资料的连接”。

Skill 同时记录当前任务、关联对话、代码版本和检查材料，执行前核对计划，复核时核对本轮证据。发送状态不明时先确认原消息，避免重复派工；中断时根据记录与实际项目接续。

这些记录帮助双方保持一致；检查是否覆盖目标，仍依赖真实执行与判断。用户体验尚未验收时，会明确保留待验收状态。

## 核心能力

| 能力 | 对使用者的作用 |
|---|---|
| 双向判断 | Codex 可以根据实际项目修正方案，范围内的小修复继续推进 |
| 任务与代码版本绑定 | 避免错接对话、执行旧计划或复核错误版本 |
| 发送前记录与重复保护 | 发送不确定时先检查，迟到的旧回复不混入新任务 |
| 工程与体验分别验收 | 检查结果、页面预览、用户体验都有明确状态 |
| 按需连接与中断接续 | 保存进度，只在需要时启动连接服务 |
| 进程身份核验与只读诊断 | 关闭前核对服务身份，诊断不顺带修改连接配置 |

支持只读 MCP、OAuth、配对、文件边界与执行记录。

### 项目资料如何被访问

ChatGPT 的读取连接只提供读取工具，文件修改由 Codex 执行。默认敏感路径过滤与 `.c2cignore` 用于限制共享内容；授权范围仍应选择具体项目，不能把过滤当作所有秘密都能自动识别的保证。

**经连接读取的内容会发送给 ChatGPT。** 连接凭据保存在共享目录之外，不需要粘贴到聊天中。不同连接方式使用相应的认证：HTTP 桥使用 OAuth 与配对；官方隧道接法依靠隧道权限和运行凭据。具体配置交给 [连接指南](silas-gpt-codex-orchestrator/references/connection.zh-CN.md)。

## 常见问题

**一定要使用 GPT-6 Astra 吗？**

不固定模型，保留你的选择。当前真实案例使用了 GPT-6 Astra；换模型或账号后，需要检查其实际可用工具与连接能力。

**我需要分别给 ChatGPT 和 Codex 发提示词吗？**

在消息传递工具、连接和授权都具备时，向 Codex 交办即可。连接不可用时会明确说明；经你同意可以手动转发，但那时不能称为自动连通。

**我已经能用 ChatGPT，为什么还需要配置？**

登录聊天与允许它读取本地项目是不同步骤。当前账号还需要具备所选连接方式要求的功能和权限，实际检查后才能确认。

**是否需要额外付费？**

Skill 的安装不会替你购买服务。ChatGPT、Codex 及所选连接服务的可用条件和使用限制，需要按你的账号核实。双端协作会增加模型使用量，不能直接当作省钱方案。

**连接失败怎么办？**

对 Codex 说：“检查这个项目的连接，告诉我卡在哪一步，保留已经完成的工作。”它应区分本机服务、账号登录、权限和真实文件读取。若需要你处理，一次说明一个必要动作。

**会一直在后台运行吗？会自动更新吗？**

连接按需启动。完成后停止本轮启动的服务；借用已有服务时保持原状。默认不设置开机启动、后台自动唤醒或每日更新。需要更新时主动提出，先核对来源版本与本地修改。

**换一个项目能直接用吗？**

可以复用已经准备好的程序，但需要重新明确新项目的共享范围、对话和记录，不能沿用其他项目的授权。

**支持哪些电脑？**

本版已在 macOS Codex 桌面环境完成真实协作测试。任务记录脚本使用 macOS/Linux 文件锁；Linux 尚需在实际环境验证，Windows 原生暂不支持该脚本。其他运行环境不能仅凭安装成功推定完整闭环可用。
