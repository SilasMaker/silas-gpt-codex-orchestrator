# 第一次使用：让两个 AI 配合，把一个想法做出来

[English](getting-started.md) | 简体中文

Silas GPT Codex Orchestrator 是一套让 Codex 组织协作的工作方法。安装后，你可以让 ChatGPT 帮忙想方案、检查成果，让 Codex 在你的项目里修改文件、运行检查，把结果交给你体验。

你不必先学会写代码，但需要说清楚“想做什么”和“怎样才算好用”。

## 它能帮我做什么？

比如，你想做一个可以打勾的任务进度页：

1. 你告诉 Codex：“我想看到今天完成了多少任务，刷新后进度还在。”
2. Codex 把目标交给 ChatGPT。ChatGPT 读取你允许分享的项目，提出方案。
3. Codex 核对方案，实际修改页面并测试。
4. ChatGPT 读取改动和本轮检查记录，指出问题或确认工程检查通过。
5. Codex 把可打开的页面交给你。你试用后说哪里还需要改。

适合尝试个人介绍页、任务清单等小网页，给现有项目增加一个小功能，或排查一个能够复现的问题。它能组织这些工作；具体能否完成，还取决于项目、可用工具与连接条件。

## 相比只用 GPT 或 Codex，有什么好处？

对新手最直接的价值是：**少做两个 AI 之间的传话人，多得到一轮针对实际成果的检查。** 这套方法不保证每项任务都比单独使用 Codex 更快、更好。

先分清两件事：同一个界面方便你查看讨论、制作进度和页面预览，减少切换窗口；背后的消息传递与项目连接，才让双方能够配合。单纯把两个窗口并排放置，并不会提升 AI 的能力。

| 方式 | 比较适合的事情 | 你需要承担的工作 |
|---|---|---|
| 只在 GPT 普通聊天中做 | 讨论想法、梳理需求、比较方案 | 没有连接项目执行工具时，需要自己把方案落实、把结果带回来 |
| 只在 Codex 中做 | 直接修改项目、运行检查、完成明确任务 | 可以直接交办；Codex 本身也能规划和复核 |
| GPT 与 Codex 协作 | 需要反复讨论、制作、检查的项目 | 提出目标、确认共享范围、体验成果并反馈 |

这里的分工是人为安排的，不意味着 GPT 天生只会思考，Codex 只会执行。

这个 Skill 额外提供的价值主要有三点：

1. **减少手动搬运信息。** 连接可用时，不用自己把 GPT 的方案复制给 Codex，再把代码、报错和检查结果搬回 GPT。
2. **增加一个单独的复核视角。** Codex 完成修改后，ChatGPT 再围绕目标检查代码和证据，有机会发现遗漏。两个 AI 也可能犯同样的错误，复核不能替代真实测试。
3. **让双方核对同一轮成果。** Skill 记录任务和代码版本，要求复核本次修改与本次检查，减少“看着旧代码，评价新结果”的混乱。

我们在任务进度页的真实测试中，做了“重置与撤销”功能。Astra 在规划中提出：重置按钮禁用后，键盘焦点应该移到撤销按钮；手动勾选后，要取消旧撤销资格。Codex 随后实现并实际验证，Astra 再读取新代码和本轮输出复核。这体现了协作过程的价值，但一次测试不能证明它优于 Codex 单独完成。

**适合想把一个小项目认真做完，又不想自己反复在两个 AI 之间复制粘贴的人。** 你负责说清目标、体验成果，Skill 帮你组织讨论、制作和复核。

代价也要考虑：首次连接更麻烦，多一轮讨论会增加等待和模型使用量，不保证更便宜或完全没有错误。改一句文案、修一个明确的小问题，单独用 Codex 往往更省事；当任务值得多一轮审查时，这种协作才更有价值。

## 一段话安装

不用自己先学会 git、Node 或终端操作。把下面这段话复制给 Codex，让它检查环境并带你安装；账号登录和必要授权仍需要你参与。

安装来源为本仓库；如果已经下载，也可以提供实际的本地 Skill 文件夹路径。

```text
请帮我安装并配置 Silas GPT Codex Orchestrator。安装来源：https://github.com/SilasMaker/silas-gpt-codex-orchestrator。我是新手，请尽量替我完成可以自动处理的步骤，用简单的话告诉我进度。

1. 先读取这个 Skill 的说明，检查本机环境、已有安装和连接状态。按文档准备必要依赖，复用可用环境，保留已有个人修改；不自动购买服务或升级套餐。
2. 安装完整的 silas-gpt-codex-orchestrator 文件夹到当前 Codex 使用的 skills 目录，包括说明、引导、脚本和运行源码，不能只复制 SKILL.md。按文档准备运行组件，检查 Codex 能否识别；如果需要新开对话或重启，请告诉我下一步。
3. 用简单的话介绍它能做什么。为首次连接使用一个独立、无敏感内容的测试项目，只允许 ChatGPT 读取这个项目。
4. 按随附连接指南，根据当前账号与本机条件配置支持的连接方式。可用时使用 Codex 内置浏览器；确实需要我登录、验证码或授权时，一次只告诉我一个必要动作。密码和密钥留在安全的本机配置或对应网页，不让我粘贴进聊天。
5. 让 ChatGPT 真实读取测试项目，再修改测试文件、重新读取并核对新内容，确认不是只安装了文件或只显示“已连接”。若连接不可用，说明具体卡点并保留进度，不把模拟或人工转发说成自动连通。
6. 完成后给我一份简短结果：Skill 是否已安装并被识别、ChatGPT 是否真实连通、测试是否通过、还有什么需要我处理，以及开始第一个小项目可以直接复制的一句话。验证结束后按需关闭本轮启动的连接服务。
```

已经安装的用户可以跳过安装提示，继续下方准备检查与首次使用。

## 安装以后，还要准备什么？

**安装完成，表示 Codex 有了这套工作说明；ChatGPT 的连接还需要单独检查。**

| 你准备的东西 | 用来做什么 |
|---|---|
| 能读取这个 Skill、操作本地文件的 Codex 环境 | 执行项目修改与检查 |
| 可登录的 ChatGPT，以及当前账号可用的连接功能 | 参与讨论并读取项目资料 |
| 一个明确的项目文件夹 | 确定这次做什么、允许读取哪些文件 |
| 一个小目标 | 让第一轮有能够实际体验的结果 |

目前我们在 macOS 的 Codex 桌面环境完成过真实协作测试。其他环境仍需现场检查；Windows 原生尚不支持本版任务记录脚本，不能承诺直接可用。

运行组件和连接服务由 Codex 根据本机情况检查、准备；完整链路还需要浏览器消息传递能力。登录、验证码等需要你在相应页面完成。是否能使用所需连接功能，要检查你的实际账号，不能只看模型名字或套餐名称。遇到收费或升级选项，先弄清原因再决定。

这里说的 MCP，可以先理解成“让 ChatGPT 按允许范围读取项目资料的连接”。只读连接本身不修改文件，Codex 负责修改；读取到的内容会发给 ChatGPT，因此只选择本次项目，密钥和私密资料不要放入共享范围。

把 ChatGPT 放在 Codex 右侧浏览器里，方便你看双方的过程。**两个窗口摆在一起并不会自动互通**，仍要完成连接与真实读取检查。也不需要你分别给两个窗口复制一套角色提示词：工具和授权具备时，由 Codex 按 Skill 转交消息。

## 第一次，发这一句话就够了

在能够读取该 Skill 的 Codex 对话里发送：

> 使用 $silas-gpt-codex-orchestrator。我是第一次使用，请先用简单的话介绍用途，检查我还缺哪些准备。连接就绪后，带我用一个独立演示项目做可交互的任务进度页：能勾选任务、显示进度，刷新后保留结果。先做一个能体验的小版本，完成后给我预览和实际检查结果。

Codex 应先告诉你哪些已就绪、哪些待检查，然后处理必要的连接步骤。如果你已经指定项目或同意共享，不需要重复回答；如果没有项目，它会帮助你选定独立演示目录。

不懂设置时，可以说：“我不懂这个步骤，请告诉我现在只需要点哪里，以及为什么。”不要把登录密码或连接密钥粘贴到聊天中。

## 我怎么知道它真的开始协作了？

你会看到“检查连接 → 讨论方案 → 制作 → 复核 → 可以体验”的进度。连接成功应有 ChatGPT 实际读到本次项目的证据；完成时应有能打开的成果，以及真实检查过和还没检查的内容。

只显示“已安装”、设置页显示“已连接”，或者模型说“我看过了”，都不足以确认完整流程成功。连接暂时不可用时，Codex 应说明卡在哪一步并保留进度；若你同意人工转发，可以继续，但需要明确这时没有自动连通。

第一次拿到页面，可以试三件事：勾选一个任务，看看进度是否变化；刷新，看看是否保留；缩窄窗口，看看是否还能正常操作。你的实际感受决定下一步怎么改。

## 以后怎么用？

已有项目时，在该项目对应的 Codex 对话中说：

> 使用 $silas-gpt-codex-orchestrator，在当前项目给任务清单增加“重新开始”和一次“撤销”功能。先核实连接，只做这一个小改动，完成后给我预览与真实检查结果。

需要调整体验时，描述你观察到的问题：

> 手机里“重新开始”按钮不容易发现。请让 ChatGPT 和 Codex 一起检查，只调整这个操作区，再给我手机预览。

中断后可以说：“继续刚才的协作，先检查已完成的内容和连接状态，不要从头重做。”任务结束后，本轮启动的连接服务按需关闭，下次用时再启动；安装这个 Skill 不会让两个 AI 永久在后台工作。

## 你负责什么？AI 负责什么？

你负责目标、允许处理的项目和最终体验判断。ChatGPT 负责参与规划和复核，Codex 负责判断方案、实际执行和提供证据。双方都可能犯错，复核通过仍需要你打开成果看看。

这套方法的价值是：从“请 AI 帮我做”，变成一个有方案、有实际修改、有检查、有反馈的工作过程。第一次先把一个小功能用起来，再决定是否用于更大的项目。
